- **작성일**: 2026-11-17
- **버전**: v0.13.0
- **담당 AI**: Claude Code(설계·제작)
- **연관 문서**: [컨셉](../Planning/01-01-concept.md) v0.12.0, [시스템 기획](../Planning/02-01-system-design.md) v0.1.0, [크레딧·AI 기록](../Event/credits-and-ai-log.md)

> 표기: `D-ID`는 사용자 결정, `[제안]`은 에이전트 제안(미확정)이다. **도트(픽셀아트) 스타일 중심은 사용자 결정(D-035)**이고, 크기·팔레트 등 세부는 `[제안]`이다.

## 1. 제작 방식

이 게임의 그림은 **코드로 그린다.** Claude Code에는 이미지 생성 기능이 없어서, 그림을 그리는 Python 코드(레시피)를 작성해 PNG를 만든다.

| 대상 | 방식 | 위치 |
| --- | --- | --- |
| 타일·아이콘·UI 조각 | Python(Pillow) 레시피 → PNG | `Art/recipes/*.py` → `Art/Export/` |
| 층 어긋남·글리치·스캔라인 같은 화면 효과 | Unity 셰이더(Shader Graph 또는 HLSL) | `Unity/Assets/_Project/Shaders/` |
| 글꼴 | OFL 등 재배포 가능한 무료 글꼴만 | 라이선스를 크레딧 기록에 남김 |

- 이 게임의 아트 방향(청사진 — D-019, 감시 화면, 프로그램 창)은 선과 도형 위주라 코드 제작과 잘 맞는다.
- 외부 유료 이미지 생성 API는 사용자가 승인한 경우에만 쓴다. **API 키는 저장소에 기록하지 않는다**(AGENTS.md 보안 규칙).
- 다른 저장소의 개인용 도구 코드를 가져오지 않는다. 이 저장소의 `tools/art/`는 이 프로젝트용으로 새로 작성했다.

## 2. 실행 방법

```bash
python -I tools/art/build_art.py            # 모든 레시피 실행
python -I tools/art/build_art.py tiles_mvp1 # 특정 레시피만
```

- 공용 함수: `tools/art/artkit.py` (팔레트, 격자, 화살표, 빛 번짐, 저장, 미리보기 시트)
- 출력: `Art/Export/<종류>/<이름>.png`, 목록은 `Art/Export/manifest.json`
- 검수용 미리보기: `Art/Export/preview/*.png`
- 필요 환경: Python 3.12, Pillow(설치 확인함). 추가 설치 없음.

## 3. Unity 반입

- 확정된 PNG만 `Unity/Assets/_Project/Art/`로 복사한다. 시안은 반입하지 않는다.
- 임포트 설정 `[제안]`: Sprite(2D and UI), **Pixels Per Unit = 32**(D-039), **Filter Mode = Point (no filter)**, **Compression = None**, Mip Map 끔.
- 화면은 Pixel Perfect Camera(URP 2D) 사용을 검토한다. 기준 해상도 **640×360**(32px 타일 20×11.25칸), 정수 배율 확대 `[제안]`.
- 레시피를 다시 실행해 그림이 바뀌면 같은 파일 이름으로 다시 복사한다(.meta 유지).

## 4. 스타일 기준 — 도트 중심(D-035)

공통 기준은 기획 저장소의 도트 리소스 가이드(검은 남색 외곽선, 제한 팔레트, 큰 색면, 안티앨리어싱 금지)를 따른다. 이 프로젝트의 세부값은 아래 `[제안]`이다.

| 항목 | 제안값 |
| --- | --- |
| 논리 크기 | 타일·인물·조준틀 **32×32 px**, PPU 32 — D-039 |
| 외곽선 | 논리 1px, 짙은 남색(`K`) |
| 팔레트 | 공유 팔레트 38색(타일·인물 23색 + 배경 전용 8색 + 초상 전용 7색)(`tools/art/artkit.py`의 `PIX`가 정본). 레시피는 팔레트 밖 색을 쓰면 실패하도록 검사 |
| 현실 층 | 어두운 회청 바닥, 벽돌 무늬 벽, 갈색 문 |
| 설계도 층 | 반투명 대신 **체커 디더**(한 칸씩 건너 청사진 파랑) + 가운데 격자 + 하늘색 도면 선. 현실 위에 겹쳐 보여 지우기처럼 보이지 않음(D-015) |
| 강조색 | 경고·조준 = 분홍빨강, 완료·출구 = 민트, 체크 지점 = 노랑 |
| 금지 | 안티앨리어싱, 블러·빛 번짐, 정수 배율이 아닌 확대 |
| 배경 | **여러 레이어로 구성**하고 Unity에서 겹친다 — D-041. **비·별 같은 별도 이펙트·파티클은 넣지 않는다** — D-040. 합본 PNG는 확인용 |

참고: v0.1.0의 선·빛 번짐 방식 시안(64px)은 도트 방향 결정으로 폐기하고 같은 레시피를 도트로 다시 작성했다. 앞 절의 `glow()` 등 비도트 함수는 도트 리소스에 쓰지 않는다.

## 4-0. 해상도 4배 규격(D-075) — 2026-11-18

| 항목 | 이전(D-039) | 새 규격(D-075) |
| --- | --- | --- |
| 기본 단위 | 32px | **128px** |
| 게임 화면(기준 해상도) | 640×360 | **2560×1440**(비율 그대로) |
| 방 한 칸(섹터) | 160×96 | **640×384** |
| 인물 | 32×32 | **128×128** |
| UI·글자 | 5×7 도트 글꼴 | 4배 디테일로 다시 그림(글꼴은 20×28 칸 또는 새 도트 글꼴) `[제안]` |
| 외곽선 | 1px | **4px 두께감 유지 또는 1~2px 세밀선** — 본그림 단계에서 결정 `[제안]` |

- 비율은 그대로이므로 레벨 데이터의 섹터 좌표는 4배만 하면 된다. 규칙 판정 값(px 단위 속도·폭)도 4배.
- **렌더링 위험**: 지금의 CPU 캔버스 합성(640×360)은 4배(2560×1440, 픽셀 16배)에서 Web 성능이 크게 떨어질 수 있다 → GPU 스프라이트 렌더링(정수 배율 유지)으로 바꾸는 구현 작업이 필요하다(W-009 예정).
- **화면 배율 처리 — D-076**: 2560×1440 기준 그림을 화면 크기에 맞게 줄이거나 늘릴 때 **부드러운 필터를 허용**한다(고해상도 도트로 취급). 1920×1080에서는 0.75배로 부드럽게 줄어든다.
  - 그림을 **만들 때**는 지금처럼 안티앨리어싱 없이 픽셀 단위로 그린다(D-035). 부드러움은 화면에 맞춰 크기를 바꿀 때만 생긴다.
  - 화면 비율이 16:9가 아니면 레터박스.
  - Unity 임포트: Filter Mode = **Bilinear**(축소용), 압축 없음, Mip Map 끔 `[제안]`. 이전의 Point 필터 규칙(§3)은 4배 그림에는 쓰지 않는다
- 본그림 1차: 조력자 128px(`Art/recipes/char_runner128.py`) — 명암 3단, 외곽선 2px `[제안]`, 걷기·기다림·떨어짐 좌우
- 애니메이션 기준 **30 FPS**(D-077). 천천히 바뀌는 반복은 manifest `holds`로
- 애니메이션 도구: `tools/art/anim.py`(프레임 시트·GIF 미리보기·manifest: 프레임 좌표·FPS·loop·기준점). 밑그림: `Art/recipes/anim_sketch.py`.
