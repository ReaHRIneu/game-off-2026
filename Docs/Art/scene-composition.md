## 0. 결정

- 배경 이미지는 **방 / 움직이는 오브젝트 / 상호작용하는 오브젝트 / 조명 오브젝트 등으로 구분**하고, **각자의 역할로 작동**하게 만든다 — D-073
- 배경 이미지에는 비 같은 별도 이펙트·파티클을 넣지 않는다(D-040). 조명은 이펙트가 아니라 **상태를 가진 오브젝트**로 다룬다 `[제안]`

| 문제 | 예 |

## 2. 레이어 구분 `[제안]` — 뒤에서 앞 순서

| 번호 | 레이어 | 무엇 | 엔진에서의 역할 | 상태·변화 |
| --- | --- | --- | --- | --- |
| L0 | **바깥 배경** | 창밖·골목 틈으로 보이는 도시(배경 레이어 6장, D-041) | 그림만 그림. 화면 이동보다 느리게 움직이는 시차 스크롤(선택) | 없음 |
| L1 | **방 껍데기** | 섹터마다 벽·바닥·천장·창틀·외벽 | 섹터 경계와 바닥선의 기준. 섹터 전체형 설계도 겹침의 대상 | 없음(섹터 전체형은 L6에서 겹침) |
| L2 | **장식 소품** | 가구·상자·화분·빨래·포스터처럼 게임에 영향 없는 물건 | 그림만 그림. 판정 없음 | 없음 |
| L3 | **조명 오브젝트** | 천장 등·모니터 빛·간판 빛·창으로 들어오는 빛 | **켜짐/꺼짐 상태**를 가진 오브젝트. 꺼지면 빛 그림(디더 빛 웅덩이)을 그리지 않음 | 켜짐 ↔ 꺼짐. 정전(섹터 전체형 장치)과 연결 가능 |
| L4 | **상호작용 오브젝트** | 문·계단 셔터·해치·레이저·단말·중계기·출구·실패 지점 | 규칙 판정의 주인공. 현실/설계도 상태별 그림 2장 + 설계도 겹침 그림 | 상태 전환(층 어긋남) |
| L5 | **움직이는 오브젝트** | 엘리베이터 칸·철판 다리·간판 발판·컨베이어 | **위치**가 바뀌는 오브젝트. 단계·경로를 가짐 | 위치 이동(위치 어긋남, 02-02 §0-3) |
| L6 | **설계도 겹침** | 섹터 전체 청사진·오브젝트 설계도 그림 | Shift 중에만 그림 | Shift 상태 |
| L7 | **인물** | 조력자(침입자) | 이동 규칙에 따라 움직임 | 위치·방향 |
| L8 | **조준·표시** | 섹터 조준틀·화면 밖 대상 표시·안내 상자 | UI | — |

- 한 오브젝트는 **한 레이어에만** 속한다. 예: 엘리베이터는 상태(작동/멈춤)도 있지만 칸이 움직이므로 L5, 문은 L4.
- 상호작용 오브젝트에 붙은 조명(예: 단말 화면 빛)은 그 오브젝트 그림에 포함하고 L3로 따로 빼지 않는다(단순화).

## 3. 레시피 출력 구조 `[제안]`

맵 하나(`<맵 이름>`)를 그리는 레시피는 아래 파일을 낸다.

| 파일 | 레이어 | 비고 |
| --- | --- | --- |
| `scenes/<맵>/L1_shell.png` | L1 | 맵 크기 한 장 |
| `scenes/<맵>/L2_props.png` | L2 | 맵 크기 한 장(투명 배경) |
| `scenes/<맵>/L3_light_<id>_on.png` | L3 | 조명마다(빛 웅덩이 포함). 꺼짐은 그림 없음 |
| `objects/<종류>_<상태>.png` | L4·L5 | 지금처럼 오브젝트 종류별 공용 그림 |
| `scenes/<맵>/layout.json` | 전체 | **배치 정보**: 섹터 표(종류·전체형 여부), 오브젝트 목록(id·종류·레이어·섹터·x·그림 좌표·현실/설계도 상태·연결·단계), 조명 목록(id·섹터·좌표·초기 상태·연결된 장치), 인물 시작, 미션 |

- **`layout.json`을 단일 원본으로** 삼는다. Unity는 이 파일을 읽어 레벨 데이터를 만든다 → 좌표를 두 번 적지 않는다.
- L0(바깥 배경)은 지금의 `backgrounds/city_layer0~5`를 그대로 쓴다.

## 4. 엔진 그리기 순서 `[제안]`

L0 → L1 → L2 → L3(켜진 것) → L4(유효 상태 그림) → L5(현재 위치) → L6(Shift 중) → L7 → L8

## 5. 조명 오브젝트 규칙 `[제안]`

| 항목 | 내용 |
| --- | --- |
| 기본 | 조명마다 켜짐/꺼짐. 처음 상태는 `layout.json` |
| 장치 연결 | 조명은 같은 섹터(또는 지정한 섹터)의 장치 상태를 따라갈 수 있다. 예: 레이저가 켜지면 복도 붉은 경고등 켜짐, 정전 장치가 설계도 상태면 그 섹터 조명 꺼짐 |
| 표현 | 빛 웅덩이는 디더 점으로만(안티앨리어싱·블러 없음, D-035) |
| 움직임 | 깜빡임 같은 반복 연출은 1차 범위에서 제외(이펙트 금지 원칙과 맞춤) |

## 6. 바꾸는 순서 `[제안]`

1. 레시피 도구에 레이어별 출력과 `layout.json` 쓰기 기능 추가(`tools/art/`)
2. 챕터 0 새 맵 2개(`ch0_home1`, `ch0_home2`)부터 레이어로 다시 출력
3. Unity: `layout.json` 읽기, 레이어별 그리기, 조명 오브젝트(구현 지시서 W-008)
4. 챕터 1 맵(`ch1_oldtown1`)은 처음부터 이 구조로 만든다
5. 예전 맵(테스트 맵, SANDBOX)은 쓰지 않으므로 옮기지 않는다

## 7. 정할 것

1. 레이어 구분(§2) — 더하거나 뺄 레이어(예: 전경 가림막, 날씨 등)

3. 조명 오브젝트의 장치 연결(§5) 범위
4. 바꾸는 순서(§6) — W-007(진행 중) 다음에 W-008로
