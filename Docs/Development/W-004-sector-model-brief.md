## 목표

게임 장면을 **타일 격자**에서 **측면 단면도 섹터 모델**로 바꾼다. 조작은 **챕터 0 기준(왼쪽 Shift 단독 + 방향키 조준)**만 구현한다. 조합 키는 범위 밖(D-032 미정).

유지하는 것: 화면 흐름(W-002), UI 패널·탭·대화·표정(W-003), 추적도·카운트다운·게임오버·재시작, 미션·별·최고 기록, 입력 판정(왼쪽 Shift, 물리 키).

## 범위

### 1. 맵 데이터 형식

의뢰 레벨 데이터를 섹터 모델로 바꾼다(형식은 producer가 정하되 아래 정보를 담을 것).

- 맵: 층 수, 층당 섹터 수, 섹터 크기(160×96), 배경 PNG 참조, 지붕 높이·바닥 두께(manifest의 `building_test_base.png` 메타: roof 24, wall 6)
- 섹터: 위치(층, 열), 바뀌는 대상 종류 = `섹터 전체` 또는 `오브젝트`(D-065)
- 오브젝트: 종류, 소속 섹터, 섹터 안 x 위치, 현실 상태, 설계도 상태, (계단·엘리베이터) 연결 정보
- 대상 시작 위치·방향, 미션과 오브젝트 연결
- 수치(대상 이동 속도 등)는 설정 에셋에 둔다

### 2. 규칙 (02-02 §0-2, 모두 `[제안]` 상태로 구현)

| 항목 | 규칙 |
| --- | --- |
| 유효 상태 | 왼쪽 Shift 중 조준한 섹터: 섹터 전체형이면 섹터 상태, 오브젝트형이면 그 섹터의 오브젝트 전부가 설계도 상태. 그 밖은 현실 상태 |
| 조준 점프 | 조작 가능한 섹터(현실 ≠ 설계도인 것이 있는 섹터)만. 섹터 중심점 기준 `진행 축 거리 + 2 × 옆 축 거리` 최소, 동점이면 진행 축 짧은 쪽, 없으면 유지. ←→ 같은 층 우선은 이 점수로 자연히 처리 |
| 대상 이동 | 바닥선을 따라 좌우 연속 이동(속도 임시 48 px/초). 시작 대기는 기존 값 |
| 문·차단막 | 진행 방향 앞의 문이 닫힘이거나, 들어갈 섹터의 차단막이 켜짐이면 그 앞에서 기다림 |
| 끝 벽 | 층의 왼쪽·오른쪽 끝에 닿으면 돌아섬 |
| 계단·엘리베이터 | 대상 중심이 그 오브젝트 x 위치에 닿는 순간 유효 상태가 열림·작동이면 연결된 섹터의 연결 x 위치로 옮기고, 연결 정보의 방향을 바라봄. 도착한 곳의 계단·엘리베이터는 다시 타지 않음(한 번 지나갈 때까지) |
| 미션·중계기 | 대상 중심이 오브젝트 x를 지나갈 때(같은 층) 효과. 중계기는 의뢰당 1회 |
| 판정 순서 | 02-02 §7과 같음(감소가 최대치 판정보다 먼저) |

### 4. 그리기

- 장면 패널 안쪽(목업 기준 16,48 ~ 427,307, 412×260)에 **카메라로 맵 일부**를 보여 준다 — D-063
- 카메라: 조준한 섹터가 보이도록 정수 픽셀 단위로 따라감(맵 밖으로 나가지 않게). 이동 연출 시간은 설정 값
- 대상이 화면 밖이면 그 방향 가장자리에 `◀ TARGET`/`TARGET ▶` 등 방향 표시(목업 참고, 빨강)
- 조준틀 `objects/sector_cursor`(섹터 크기). Shift 중: 섹터 전체형은 `objects/bp_sector`, 오브젝트형은 `bp_sector` + 오브젝트의 `bp_*`(있는 것) 겹침
- 오브젝트는 바닥선 기준으로 그린다(문은 섹터 경계에 걸침). 시안 `scene_building.py`의 `map_with_objects()` 배치를 따른다
- 32px 타일(`tiles/*`)은 더 이상 쓰지 않는다(파일은 지우지 않음)

### 5. 정리

- 격자 전용 코드(`Board`의 타일 격자 해석 등)는 섹터 모델로 대체한다. W-001 테스트 의뢰 데이터는 지우지 말고 사용하지 않는 상태로 둔다(또는 v2로 교체)
