## 목표

지금의 **CPU 픽셀 캔버스(640×360, 매 프레임 Color32 합성)**를 **GPU 그리기(기준 2560×1440 RenderTexture)**로 바꾼다. 화면에 맞출 때는 부드러운 필터로 늘리거나 줄인다. 4배 그림이 없는 동안은 기존 32px 계열 그림을 **4배 Point(최근접) 확대**로 그려 화면이 그대로 보이게 한다.

## 범위

### 1. 그리기 기반

- `PixelCanvas`의 공개 API(Fill, Blit, BlitPart, Text, 9-slice, SetClip/ClearClip, SaveLayer/RestoreLayer 등)를 **그대로 유지**하고 내부를 GPU 그리기로 바꾼다(예: 2560×1440 RenderTexture + `Graphics.DrawTexture`/`GL` 또는 CommandBuffer). 호출하는 쪽(MenuRenderer, GameRenderer)은 가능한 한 고치지 않는다
- **좌표계**: 기존 코드는 640×360 좌표를 쓴다. 내부에서 4배해서 2560×1440에 그린다(논리 좌표 640×360 유지). 4배 그림(128 단위)을 그릴 때는 논리 좌표 1 = 실제 4px 기준으로 1:1(축소·확대 없이) 그린다
- **그림 선택**: 같은 이름의 4배 그림이 있으면 그것을, 없으면 기존 그림을 4배 Point 확대. 4배 그림 이름 규칙은 `art-pipeline.md` §4-0과 `anim/` 시트(manifest의 `frame_size`·`rects`)
- **화면 출력**: RenderTexture를 화면 크기에 맞춰 16:9 레터박스로 그리고, 필터는 Bilinear(D-076)
- 고정 층(SaveLayer)은 RenderTexture 복사로 구현해 매 프레임 배경 합성을 피한다

### 2. 애니메이션 재생(최소)

- manifest의 `anim/*_sheet.png` 정보(프레임 좌표·FPS·반복)를 읽어 프레임을 재생하는 기능
- 적용: 조력자 `anim/runner128_walk`(걷는 중), `runner128_wait`(문·차단막 앞 기다림), `runner128_fall`(해치로 떨어질 때 한 번), 좌우 `_left` 시트. 기존 32px `runner_*` 대신 사용
- **판정은 즉시, 그림은 따라간다**(animation-audit §3-1): 애니메이션이 규칙 판정·이동을 늦추지 않는다

### 3. 반입 설정

- `GameOff/Import Art`에 `anim/` 폴더 포함. 4배 그림(anim/ 및 이후 128 단위 그림)은 Filter **Bilinear**, 압축 없음, Mip 끔. 기존 32px 계열은 지금처럼 Point(4배 확대에 사용)
