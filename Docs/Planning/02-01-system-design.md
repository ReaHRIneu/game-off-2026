> 표기: `D-ID`는 사용자 결정, `[제안]`은 에이전트 제안(미확정)이다. `[임시]`는 MVP-1 구현을 위한 임시값으로, 레벨·밸런스 기획에서 바꾼다(D-032, D-033). 사용자가 다른 값을 정하면 그 값을 따른다.

## 개요

컨셉의 핵심 재미(D-013)를 5개 시스템으로 구현한다. 플레이어는 조준틀을 옮기고 왼쪽 Shift를 눌러 칸의 설계도 층을 드러낸다. 실시간으로 움직이는 대상이 그 칸을 지나가도록 타이밍을 맞추고, 추적도를 관리하며 미션을 완료한다.

## 시스템 상세

### 1. 입력·조준

- **목적**: 단축키 형식 조작(D-005)을 제공한다.
- **구조**: 조준틀(격자 좌표 1칸), 입력 상태(왼쪽 Shift 누름 여부).
- **규칙**:
  - **마우스 입력은 받지 않는다** — D-036
  - **방향키 단독 = 조준 점프**: 누른 방향에 있는 **다음 조작 가능한 칸**으로 조준이 옮겨 간다. 빈 바닥 등 조작할 수 없는 칸은 건너뛴다 — D-038
  - 조작 가능한 칸 = 현실 상태와 설계도 상태가 다른 칸 `[제안]`
  - 다음 칸 고르기 `[제안]`: 누른 방향 쪽(진행 축 거리 > 0)에 있는 후보 중 `진행 축 거리 + 2 × 옆 축 거리`가 가장 작은 칸. 같으면 진행 축 거리가 짧은 칸. 후보가 없으면 조준은 그대로
  - 조준은 처음에 시작 지점에서 가장 가까운 조작 가능한 칸에 놓인다 `[제안]`
  - **왼쪽 Shift만** 인식한다. 오른쪽 Shift는 무시한다 — D-012
  - 키 판정은 문자 값이 아니라 **물리 키 위치**로 한다(키보드 배열·Caps Lock 대응) `[제안]`
  - Shift를 누른 동안 방향키는 조합 키용으로 예약하며 MVP-1에서는 아무 동작도 하지 않는다(조합 키는 D-032) `[제안]`
  - 시스템 조작: 메뉴는 **방향키로 고르고 `Enter`로 결정**한다. `ESC`는 일시정지 — D-006, D-037
- **예외 처리**: 게임 화면이 포커스를 잃으면 자동 일시정지. 첫 화면은 "Press Enter" `[제안]`. 브라우저 포커스 문제는 T-005

### 2. 층 어긋남

- **목적**: 공간 왜곡(D-007)을 '어긋남'(D-015)으로 구현한다.
- **구조**: 각 칸은 **현실 상태**와 **설계도 상태** 두 값을 가진다(층 2개 고정, D-018).
- **규칙**:
  - 왼쪽 Shift를 누르는 동안 **조준한 칸**의 유효 상태 = 설계도 상태. 떼면 현실 상태로 돌아간다 — D-010, D-016
  - 왜곡 범위는 MVP-1에서 1칸 `[제안]`
  - Shift를 누른 채 조준틀은 움직이지 않는다(위 1번 규칙) `[제안]`
  - 칸 종류 `[임시]`:

| 칸 | 통행 | 비고 |
| --- | --- | --- |
| 바닥 | 가능 | |
| 벽 | 불가 | |
| 문(닫힘) | 불가 | 현실은 닫힘·설계도는 열림처럼 층마다 다를 수 있음 |
| 문(열림) | 가능 | |
| 방향 칸(↑↓←→) | 가능 | 대상이 밟으면 그 방향으로 진행 방향을 바꿈. 층마다 방향이 다를 수 있음 |
| 출구 | 가능 | 최종 미션 지점 |
| 체크 지점 | 가능 | 나머지 미션 지점 |
| 중계기 | 가능 | 대상이 지나가면 추적도 감소(트리거, 1회) |

  - 지우기·만들기처럼 보이면 안 된다(D-015). 설계도 상태는 청사진(D-019)으로 현실 위에 겹쳐 보인다. MVP-1은 파란 외곽선 + 반투명 표시로 대신한다 `[임시]`
- **UI 개요**: 조준한 칸의 설계도 상태를 Shift를 누르지 않아도 흐리게 미리 보여 줄지는 미정 `[제안: 미리 보기 없음 — 관찰 퍼즐 유지]`

### 3. 대상 이동

- **목적**: 실시간 진행(D-009)과 타이밍 퍼즐을 만든다.
- **구조**: 의뢰 대상 1명(MVP-1), 위치(칸), 진행 방향.
- **규칙** `[제안]`:
  - 일정 간격(임시 0.5초)마다 진행 방향으로 1칸 이동한다.
  - 이동할 칸의 **그 순간 유효 상태**가 통행 불가면 그 자리에서 기다린다(돌아서지 않음).
  - 방향 칸에 들어서면 **들어선 순간의 유효 상태** 방향으로 바꾼다.
- **흐름**: 이동 판정 → 칸 효과(방향·미션·중계기) 적용 → 다음 간격 대기.

### 4. 추적도

- **목적**: Shift 사용 시간을 자원으로 만든다(D-011).
- **규칙**:
  - 왼쪽 Shift를 누르는 동안 초당 일정량 오른다 — D-020. `[임시]` 최대 100, 초당 20(약 5초면 가득 참)
  - 손을 떼도 줄지 않는다 — D-021
  - 미션 완료 시 감소 `[임시 30]`, 중계기 작동 시 감소 `[임시 40]` — D-021
  - 최대치(100)에 도달하면 카운트다운 시작 `[임시 5초]`. 카운트다운 중 추적도가 최대치 아래로 내려가면 카운트다운 해제. 끝날 때까지 못 낮추면 게임오버 — D-025
  - 카운트다운 중에도 Shift는 쓸 수 있다(추적도는 최대치에 머묾) `[제안]`
- **상태**: 정상 → 카운트다운 → (해제 시) 정상 / (종료 시) 게임오버
- 수치는 밸런스 기획에서 정한다 — D-033

### 5. 의뢰·미션·성급

- **목적**: 목표와 평가(D-023~D-031).
- **구조**: 의뢰 1개 = 격자 장면 1개. 미션 목록 = 최종 미션 1개 + 나머지 미션 N개.
- **규칙**:
  - 최종 미션을 완료하는 순간 의뢰가 끝난다(특수 스테이지 제외) — D-027
  - 별: ★ 최종 미션 / ★★ + 나머지 절반 이상 / ★★★ 모든 미션 — D-030
  - 게임오버 또는 일시정지 메뉴의 다시 시작: **의뢰를 처음부터**(추적도·미션·대상 위치 초기화) — D-031
- **흐름**: 브리핑(미션 목록) → 플레이 → 결과(별) 또는 게임오버 → 다시 시작

### 6. 화면(프로그램 창)

`[임시]` — MVP-1은 기능 확인용 단순 도형

- 가상 프로그램 창 틀(D-008) 안에: 장면 격자, 미션 목록(완료 체크), 추적도 게이지, 카운트다운 숫자, 명령 기록 줄(누른 키 표시)
- 결과 화면: 별 개수, 다시 시작
- 실제 OS·프로그램 디자인을 흉내 내지 않는다 `[제안]`

## 컨텐츠 순환 구조

- **핵심 가치**: 별(의뢰 평가)
- **획득 → 소비 흐름**:
  1. Shift 사용 → 추적도 소비(증가)
  2. 미션 완료·중계기 작동 → 추적도 회복(감소) + 별 조건 진행
  3. 최종 미션 완료 → 별 확정. 별을 더 얻으려면 추적도 위험을 지고 나머지 미션을 먼저 해야 한다
