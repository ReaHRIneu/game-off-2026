## 0. 설계 의도

핵심 재미(D-013)는 "간단한 조작키 조합으로 주어진 상황을 퍼즐처럼 풀어 가는 것"이다. 시스템은 세 가지를 지키도록 설계한다.

1. **읽을 수 있는 규칙**: 같은 입력에는 항상 같은 결과가 나온다. 판정 순서를 고정한다(7. 판정 순서).
2. **타이밍과 자원의 긴장**: 실시간(D-009)으로 움직이는 대상에 맞춰 Shift를 누르고, 누른 시간만큼 추적도(D-011)를 쓴다.
3. **실패해도 다시 하기 쉬움**: 게임오버는 같은 의뢰를 처음부터 즉시 다시 시작한다(D-031). 막혀서 진행할 수 없는 상태(소프트락)를 만들지 않는다.

## 0-1. 공간 구조 — D-063~D-065 (2026-11-17 개편 시작)

> **이 절이 §2~§5보다 우선한다.** §2~§5의 "칸"은 타일 격자 시절 표현이며, 아래 정의로 다시 쓴다(조작키 기믹 확정 후 v0.3.0에서 일괄 개편).

- **장면 표현**: 타일 이미지가 아니라 **실제 도시 배경** 위에 **다양한 환경 요소(오브젝트)**를 둔다 — D-063
- **화면**: 맵 전체가 한 화면에 다 보일 필요는 없다. 화면은 맵의 일부를 보여 주고 이동한다 — D-063
- **타겟팅 단위 = 방 한 칸(섹터)**. 방 하나가 한 칸이다. 넓이가 2칸 이상인 큰 공간은 **가상의 경계선**으로 나눠 여러 섹터로 만든다 — D-064
- **판정 대상**: 층 어긋남으로 바뀌는 것은 **조준한 섹터 전체** 또는 **그 섹터에 속한 오브젝트**다 — D-065
- 기존 결정의 "칸"은 이제 **섹터**를 뜻한다: D-016(조준한 칸의 층 어긋남), D-038(다음 조작 가능한 칸으로 점프)

### 0-1-1. 제안 `[제안]`

| 항목 | 제안 |
| --- | --- |
| 섹터 크기 | 한 화면(640×360 중 장면 영역)에 섹터 여러 개가 보이는 크기. 예: 섹터 기본 160×96px |
| 섹터 데이터 | 섹터마다 `바뀌는 대상 = 섹터 전체` 또는 `오브젝트 목록`을 레벨 데이터에서 정한다(예: 정전되는 방 = 섹터 전체, 방 안의 문 = 오브젝트) |
| 경계선 표시 | 조준하면 그 섹터의 테두리(가상 경계선 포함)를 조준틀로 표시 |
| 조준 점프 | 조작 가능한 섹터(현실·설계도가 다른 섹터)만 대상. 점수 규칙은 §2를 섹터 중심점 거리로 계산 |
| 화면 이동 | 조준한 섹터가 화면 밖이면 정수 픽셀 단위로 화면이 따라간다. 의뢰 대상이 화면 밖이면 가장자리에 방향 표시 |
| 대상 이동 | 섹터를 잇는 길을 따라 연속 이동. 섹터 경계(문·통로)를 지날 때 그 섹터의 유효 상태로 통행 판정 |

## 0-2. 측면 단면도 섹터 모델 — D-066 (Shift 단독 기준)

> 장면은 **건물을 옆에서 잘라 본 측면 단면도**다 — D-066. 이 절은 §2~§5(타일 격자 규칙)를 대신한다. §2~§5는 참고용으로 남기며 v0.3.0에서 지운다. 조합 키 기믹은 사용자 확정 대기(D-032, D-061).

### 0-2-1. 맵 구조 `[제안]`

- 맵 = **층(가로 줄) × 방(섹터)**. 섹터는 직사각형이며 같은 층에서 좌우로 붙는다.
- 섹터 기본 크기 160×96px, 큰 방은 가로로 여러 섹터(가상 경계선은 점선으로 표시) — D-064
- 배경: 건물 단면 그림(벽·바닥·가구) + 창 너머 도시 야경(배경 레이어 재사용, D-041)
- 화면은 맵 일부만 보여 주고 따라간다 — D-063

### 0-2-2. 오브젝트·섹터 종류 `[제안]`

| 종류 | 위치 | 현실 ↔ 설계도 예 | 대상에게 주는 효과 |
| --- | --- | --- | --- |
| 문 | 섹터 사이 경계 | 닫힘 ↔ 열림 | 닫혀 있으면 그 앞에서 기다림 |
| 계단 | 섹터 안(위·아래 층 섹터를 이음) | 셔터 막힘 ↔ 열림 | 열려 있을 때 들어서면 연결된 층으로 이동 |
| 엘리베이터 | 위아래 섹터 묶음 | 멈춤 ↔ 작동 | 작동 중일 때 들어서면 연결 층으로 이동 |
| 바닥 차단막(섹터 전체) | 섹터 전체 | 닫힘 ↔ 열림 | 닫혀 있으면 섹터에 들어갈 수 없음 — D-065 "섹터 전체" 예 |
| 출구 | 섹터 안 | 같음 | 최종 미션 |
| 체크 지점(데이터 단말 등) | 섹터 안 | 같음 | 나머지 미션 |
| 중계기 | 섹터 안 | 같음 | 추적도 감소 |

- 오브젝트는 하나의 섹터에 속한다. 문은 왼쪽 섹터 소속으로 정한다.
- 조준한 섹터에서 Shift를 누르면 그 섹터 전체(섹터 전체형) 또는 그 섹터의 오브젝트 전부(오브젝트형)가 설계도 상태가 된다 — D-065

### 0-2-3. 조준 `[제안]`

- 방향키 단독: 누른 방향의 다음 **조작 가능한 섹터**로 점프(현실 ≠ 설계도인 섹터만) — D-038
- 점수: 섹터 중심점 기준 진행 축 거리 + 옆 축 가중치 × 옆 축 거리(§2와 같은 방식)
- ↑↓는 층을 오르내리는 점프, ←→는 같은 층 우선
- 조준틀 = 섹터 테두리(분홍빨강). 조준한 섹터가 화면 밖이면 화면이 따라감

### 0-2-4. 대상 이동 `[제안]`

- 대상은 바닥을 따라 **좌우로 연속 이동**한다(속도 `데이터: 대상 이동 속도`).
- 닫힌 문·닫힌 차단막 앞에서는 **기다린다**(MVP-1 규칙 유지).
- 층의 끝 벽에 닿으면 **돌아선다**(측면에서는 막다른 곳이 많아 기다리면 소프트락이 쉬움).
- 계단·엘리베이터는 **들어서는 순간의 유효 상태**가 "열림·작동"이면 연결된 층으로 옮겨 가고, 같은 방향으로 계속 걷는다.
- 체크 지점·중계기·출구는 대상이 그 오브젝트 위치를 지나갈 때 효과.

## 2. 조준

- **목적**: 원격 해커의 "커서"(D-008). 칸을 하나씩 옮기는 대신 의미 있는 칸으로 바로 옮겨 실시간 타이밍에 집중하게 한다.
- **조작 가능한 칸**: 현실 상태와 설계도 상태가 다른 칸. 같은 종류라도 방향이 다르면 조작 가능 `[구현]`
- **점프 규칙** — D-038, 세부 `[구현]`:
  1. 누른 방향으로 진행 축 거리가 0보다 큰 조작 가능한 칸을 후보로 모은다.
  2. 점수 = 진행 축 거리 + `데이터: 옆 축 가중치` × 옆 축 거리. 가장 낮은 칸으로 옮긴다.
  3. 점수가 같으면 진행 축 거리가 짧은 칸.
  4. 후보가 없으면 조준은 그대로 있다.
- **처음 위치**: 의뢰 대상 시작 칸에서 맨해튼 거리가 가장 가까운 조작 가능한 칸 `[구현]`
- **Shift 중**: 방향키는 조준 점프가 아니라 조합 키로 쓴다(MVP-1에서는 무시) — D-032

## 3. 층 어긋남

- **목적**: 공간 왜곡(D-007)을 "어긋남"(D-015)으로 표현하고 SHIFT 주제와 잇는다.
- **구조**: 모든 칸은 `현실 상태`, `설계도 상태` 두 값을 가진다. 층은 2개로 고정 — D-018
- **유효 상태**: 왼쪽 Shift를 누르는 동안 **조준한 칸**의 유효 상태 = 설계도 상태. 그 밖의 모든 칸과 Shift를 뗀 순간 = 현실 상태 — D-010, D-016
- **범위**: 기본은 1칸. 범위를 넓히는 조합 키는 02-03에서 정한다
- **지우기·만들기 금지**: 설계도 상태도 "같은 칸의 다른 상태"다. 칸을 없애거나 새로 만드는 왜곡은 없다 — D-015
- **표현**: 현실 타일 위에 청사진 타일을 겹친다(D-019, D-035). 출구·체크 지점·중계기처럼 두 층이 같은 칸에는 겹치지 않는다 `[구현]`

## 4. 칸 종류

| 칸 | 통행 | 효과 | 효과가 일어나는 때 |
| --- | --- | --- | --- |
| 바닥 | 가능 | 없음 | — |
| 벽 | 불가 | 없음 | — |
| 문(닫힘) | 불가 | 없음 | — |
| 문(열림) | 가능 | 없음 | — |
| 방향 칸(↑↓←→) | 가능 | 대상의 진행 방향을 칸의 방향으로 바꿈 | 대상이 **들어선 순간의 유효 상태** 기준 `[구현]` |
| 출구 | 가능 | 최종 미션 완료 | 들어선 순간 |
| 체크 지점 | 가능 | 해당 미션 완료(한 번만) | 들어선 순간 |
| 중계기 | 가능 | 추적도 `데이터: 중계기 감소량`만큼 감소(의뢰당 칸마다 1회) | 들어선 순간 |

- 문은 현실과 설계도에서 열림·닫힘이 다를 수 있다. 방향 칸은 두 층의 방향이 다를 수 있다.
- 새 칸 종류(감시 카메라 등)는 02-03에서 제안한다.

## 5. 대상 이동

- **목적**: 실시간 타이밍(D-009)을 만드는 움직이는 퍼즐 조각.
- **구조**: 의뢰 대상(MVP는 1명). 위치(칸), 진행 방향.
- **흐름**:
  1. 플레이 시작 후 `데이터: 시작 대기` 동안 움직이지 않는다.
  2. 이후 `데이터: 이동 간격`마다 한 번 이동을 판정한다.
  3. 진행 방향 다음 칸의 **그 순간 유효 상태**가 통행 가능이면 1칸 이동, 불가능이면 **제자리에서 기다린다**(되돌아가지 않음) `[구현]`
  4. 들어선 칸의 효과를 적용한다(4. 칸 종류).
- **막힘**: 기다리는 동안에도 이동 판정은 간격마다 계속한다. 길이 열리는 다음 판정에 바로 지나간다 `[구현]`
- **소프트락 방지**: 대상이 영원히 막혀도 플레이어는 일시정지 → 다시 시작으로 빠져나올 수 있다. 의뢰 설계에서 "Shift 없이는 영원히 막히는 구조"는 의도된 퍼즐로 보고 허용한다 `[제안]`

## 6. 추적도

- **목적**: Shift 사용을 공짜가 아닌 **시간 자원**으로 만들어, 언제 누를지 판단하게 한다(D-011).
- **상태**: `정상` → (최대치 도달) → `카운트다운` → (시간 종료) → `게임오버`. 카운트다운 중 최대치 아래로 내려가면 `정상`
- **증가**: 왼쪽 Shift를 누르는 동안 초당 `데이터: 추적도 증가 속도`. 카운트다운 중에도 Shift를 쓸 수 있고 값은 최대치에 머문다 `[구현]` — D-011, D-020
- **감소**: Shift를 떼도 줄지 않는다. 미션 완료(`데이터: 미션 감소량`)와 중계기(`데이터: 중계기 감소량`)로만 줄어든다. 0 아래로 내려가지 않는다 — D-021
- **카운트다운**: 최대치에 닿으면 `데이터: 카운트다운 길이`부터 줄어든다. 0이 되면 게임오버 — D-025
- **게임오버**: 의뢰를 처음부터 다시 시작한다(추적도·미션·대상 위치 초기화). 브리핑 대화는 건너뛴다 `[구현]` — D-029, D-031

## 7. 한 프레임의 판정 순서 `[제안]`

QA T-011(같은 순간에 최대치 도달과 미션 완료가 겹치는 경우)의 기준이다.

1. 입력 읽기(조준 점프, Shift 상태)
2. 유효 상태 갱신(조준 칸의 층)
3. 추적도 증가(Shift 누름 시간만큼)
4. 이동 간격이 되었으면 대상 이동 → 칸 효과(미션 완료·중계기 감소)
5. 최대치·카운트다운 판정
6. 최종 미션 완료면 의뢰 종료(종료 대화로)

→ 같은 프레임에 최대치에 닿아도 그 프레임의 미션·중계기 감소가 먼저 적용된다.

## 8. 미션·성급

- **목적**: 클리어 자체는 쉽게 하고, 더 잘하고 싶은 플레이어에게 위험을 진 선택지를 준다.
- **구조**: 의뢰마다 최종 미션 1개 + 나머지 미션 N개 — D-024
- **종료**: 최종 미션을 완료하는 순간 의뢰가 끝난다(특수 스테이지 제외) — D-027
- **별**: ★ 최종 미션 / ★★ 최종 + 나머지 절반 이상 / ★★★ 전부 — D-028, D-030. 계산식: `나머지 완료 수 × 2 ≥ 나머지 전체 수`이면 ★★ `[구현]`
- **예상 별**: 플레이 중 "지금 끝내면 받을 별"을 MISSION 탭에 표시한다. 게임오버 때는 표시하지 않는다 `[구현]`
- **최고 기록**: 의뢰별 최고 별만 저장한다. 낮은 별로 다시 클리어해도 최고 기록은 내려가지 않는다 `[구현]`
