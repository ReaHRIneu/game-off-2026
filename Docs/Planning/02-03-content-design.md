> 표기: `D-ID` = 사용자 결정, `[구현]` = 구현되어 동작 중(사용자 확인 전), `[제안]` = 에이전트 제안.
> 수치는 정확한 데이터가 아니라 **의도를 설명하기 위한 값**이다. 확정 수치는 밸런스 기획에서 정한다(D-033).

## 1. 왜 이 콘텐츠인가

- **제작 의도**: GitHub Game Off 2026(주제 SHIFT)에 1인으로 13일 안에 완성하는 포트폴리오 작품(D-001). 평가자는 짧게 플레이하고 6개 항목으로 평가한다.
- **핵심 재미**: SF 디스토피아의 뒷세계 해커가 되어 의뢰를 맡고, 간단한 조작키 조합으로 상황을 퍼즐처럼 푼다(D-013).
- 그래서 콘텐츠는
  1. **한 의뢰가 짧다** — 평가자가 몇 분 안에 핵심 재미를 느껴야 한다.
  2. **의뢰마다 새 것을 하나만 가르친다** — "Shift 하나에서 조합이 늘어나는" 진행(D-005)을 콘텐츠 순서로 보여 준다.
  3. **클리어는 쉽고, ★3은 어렵다** — 처음 보는 사람도 끝까지 가고, 잘하는 사람은 다시 도전한다(D-026~D-030).

## 2. 콘텐츠 구성 요소

| 요소 | 역할 | 상태 |
| --- | --- | --- |
| 의뢰(스테이지) | 퍼즐 한 판. 장면 격자 + 대상 + 칸·장치 + 미션 + 대화 | 구조 `[구현]`, 실제 의뢰는 테스트 1개 |
| 칸·장치 | 퍼즐의 규칙 조각(02-02 §4) | 7종 `[구현]`, 새 요소 `[제안]` |
| 미션 | 클리어 조건과 별 조건 | 최종 + 체크 지점 `[구현]` |
| 조합 키 | 의뢰가 진행될수록 늘어나는 조작 | `[제안]` — D-032 |
| 대화 | 의뢰의 이유와 해커의 성격을 전달(무뚝뚝 — D-052) | 구조 `[구현]`, 대사 임시 |
| 별·최고 기록 | 다시 도전할 이유 | `[구현]` |

## 3. 칸·장치 콘텐츠

### 3-1. 구현된 칸(7종)

바닥, 벽, 문, 방향 칸, 출구, 체크 지점, 중계기 — 규칙은 02-02 §4.

| 칸 | 퍼즐에서의 역할 |
| --- | --- |
| 문 | "언제 열어 둘까" — 대상이 지나가는 순간에만 짧게 연다(타이밍) |
| 방향 칸 | "어디로 보낼까" — 들어서는 순간에 방향을 바꿔 길을 고른다(경로 선택) |
| 체크 지점 | "더 갈까 멈출까" — 별을 위한 우회 경로를 만든다(위험과 보상) |
| 중계기 | "숨 돌리기" — 추적도를 회복시켜 다음 Shift를 쓸 여유를 준다(자원 관리) |

### 3-2. 새 요소 후보 `[제안]`

| 요소 | 규칙(안) | 퍼즐 역할 | 1차 범위 판단 |
| --- | --- | --- | --- |
| 감시 카메라 | 정해진 칸들을 비춘다. 시야 안의 칸에서 Shift를 누르면 추적도가 2배로 오른다 | "어디서 누를까" — 같은 문이라도 위치에 따라 비용이 다름 | 넣는 안. 기존 규칙(추적도)만 바꿔서 구현이 가볍다 |
| 번호 장치 | 문·카메라에 1~9 번호표. `Shift + 숫자`로 조준 없이 그 장치를 어긋나게 한다 | "멀리 있는 것을 동시에" — 조준 점프의 한계를 넘는다 | `Shift + 숫자`를 넣으면 같이 들어감 |
| 대상 2명 | 대상이 두 명. 각자 지정된 출구로 | "두 흐름을 동시에" — 최종 의뢰의 종합 시험 | 선택. 이동·미션 데이터를 늘려야 해서 중간 비용 |
| 버티기 의뢰 | 출구 대신 제한 시간 동안 게임오버 없이 버티면 클리어(특수 스테이지, D-027) | 추적도 관리만 집중 시험 | 선택. 일정 여유가 있으면 마지막에 |

## 4. 조합 키 콘텐츠 `[제안]` — D-032

키보드에서 원래 쓰는 뜻을 살린다(유사 게임 조사에서 "실제 기능과 다르다"는 비판이 있었음).

| 조합 | 원래 뜻 | 게임 안 의미 | 비용 |
| --- | --- | --- | --- |
| `Shift + 방향키` | 선택 영역 넓히기 | Shift를 누른 채 방향키를 누를 때마다 어긋남 범위가 그 방향으로 1칸 넓어짐. Shift를 떼면 범위 초기화 | 범위 칸 수에 비례해 추적도가 빨리 오름 |
| `Shift + 숫자` | 두 번째 기능 | 번호 장치를 원격으로 어긋나게 함(누르는 동안) | 기본과 같음 |
| `Shift + 영문` | 대문자 | **1차에서는 쓰지 않음**. 조합이 많아지면 "간단한 조합"(D-013)이 깨지고, 13일 일정에 비해 학습 부담이 큼 | — |

- 확장 방향: 2차 버전에서 `Shift + 영문`을 "같은 글자가 붙은 칸 묶음을 한꺼번에"로 넣을 수 있다.

## 5. 챕터 구조 — D-060~D-062

- 의뢰는 **챕터**로 묶는다. **챕터마다 컨셉**을 정한다 — D-060
- **챕터를 넘길 때마다 조작키가 새로 하나 추가**된다. 한 챕터 안에서는 새 조작키가 늘지 않는다 — D-061 (D-005 "조합이 점점 늘어남"을 챕터 단위로 구체화)
- **챕터 0은 Shift 키만 쓰는 튜토리얼 버전**이다 — D-062

### 5-1. 챕터 라인업 `[제안]`

| 챕터 | 새 조작키 | 컨셉(안) | 의뢰 수(안) | 의도 |
| --- | --- | --- | --- | --- |
| 0 | 왼쪽 `Shift` (튜토리얼) | **주인공이 사는 건물에 도둑이 침입** — 인물이 주인공에게 닿지 못하게 막음(D-069). 이 인물이 이후 조력자로 화면 속에서 활동(D-070) | 2 | 조준·Shift를 "막는 쪽"으로 먼저 익힘 |
| 1 | `Shift + 방향키`(기믹은 02-04 확정 대기) | **구시가지 — 여러 빌딩을 지나가는 컨셉**(D-067). 낡은 건물 여러 채를 건물 사이 틈·옥상·골목으로 이어 지나감 | 2 | 건물을 넘나드는 길 찾기 |
| 2 | `Shift + 숫자`(기믹은 02-04 확정 대기) | **사람이 없는 공장지대**(D-068). 자동으로 돌아가는 기계·컨베이어·로봇 설비 | 2 | 사람 대신 기계를 다루는 동시 처리 |
| (3) | (`Shift + 영문` 또는 없음) | **관리 타워** — 최종 의뢰. 배운 조작 종합 | (1) | 일정 여유가 있을 때만(2차 후보) |

- 1차 범위: 챕터 0~2, 의뢰 6개. 이유: 기능 구현 3일 + 의뢰 제작 4일 기준으로 하루 1~2개. 평가자 플레이 10~15분 목표.
- 의뢰 하나의 크기(의도): 격자 12×5 ~ 13×7, 미션 3개(최종 1 + 나머지 2), 첫 클리어 1~2분.

### 5-2. 챕터 0 튜토리얼 버전 `[제안]`

| 항목 | 일반 의뢰 | 챕터 0(튜토리얼) |
| --- | --- | --- |
| 쓸 수 있는 키 | 챕터까지 배운 조작키 | 왼쪽 Shift와 방향키(조준)만 |
| 대화 | 시작·종료 때만(D-045) | 시작·종료 대화에 더해, **단계마다 안내 메시지**(예: "← → 로 조준을 옮겨라", "SHIFT 를 누르고 있어라")가 LOG에 뜸 — D-045와의 관계는 아래 확인 필요 |
| 안내 표시 | 없음 | 지금 눌러야 할 키 배지를 장면 위에 크게 표시 |
| 게임오버 | 있음 | **없음** — 추적도가 가득 차면 경고만 하고 계속(실패 부담 제거) |
| 별 | 있음 | 있음(★ 규칙 학습용) |
| 의뢰 | — | 0-1: 조준 점프 + Shift로 문 열기 / 0-2: 방향 칸 + 추적도·중계기 + 체크 지점과 별 |

### 5-3. 바탕화면에서의 챕터 표시 `[제안]`

- 바탕화면(D-058)에 챕터를 **폴더 아이콘**으로 둔다: `CH0_HOME`, `CH1_OLDTOWN`, `CH2_FACTORY`
- 폴더를 열면(Enter) 그 챕터의 의뢰 파일 아이콘이 보이고, 의뢰를 고르면 오른쪽 상세 패널(D-059)
- 다음 챕터 폴더는 앞 챕터 의뢰를 모두 ★1 이상으로 클리어하면 열린다
- 챕터가 열릴 때 "새 조작키 추가" 알림을 띄운다

### 5-4. 난이도 흐름(의도)

| 의뢰 | ★1 | ★3 |
| --- | --- | --- |
| 0-1, 0-2 | 매우 쉬움 | 쉬움 |
| 1-1 | 쉬움 | 보통 |
| 1-2 | 보통 | 보통~어려움 |
| 2-1 | 보통 | 어려움 |
| 2-2 | 보통~어려움 | 어려움 |

## 6. 의뢰 제작 규칙 `[제안]`

1. 모든 의뢰는 **★1 경로가 반드시 있다**. ★1은 그 의뢰의 새 요소만 이해하면 갈 수 있게 한다.
2. **★3 경로는 위험을 진다**: 추적도를 더 쓰거나, 카운트다운에 들어갈 수 있는 길로 둔다.
3. 중계기는 ★3 경로 위나 그 근처에 둔다(위험을 진 사람에게 회복 수단).
4. 새 요소는 처음 나올 때 **안전한 곳에서 한 번** 써 보게 한다(실패 비용이 낮은 위치).
5. 대화(브리핑)는 3~5줄. 챕터 첫 의뢰의 브리핑은 새 조작키를 소개한다. 이번 의뢰의 목표와 새 요소를 한 줄로 알려 준다. 해커는 짧게 답한다(D-052).
6. 의뢰 데이터는 두 층 문자 격자 + 미션 목록 + 대화로 만든다(현재 구현 형식).

## 7. 확장 방향(2차 이후)

- `Shift + 영문` 묶음 조작, 대상 여러 명, 버티기 외 특수 스테이지(시간 제한 탈출 등)
- 의뢰인 초상(MVP는 주인공만 — D-047)
- 주인공 이야기를 잇는 의뢰 묶음(시나리오 기획)

## 8. 정할 것

1. 챕터 라인업(§5-1): 챕터별 컨셉, 새 조작키 순서(범위 → 번호), 챕터 3 여부, 챕터당 의뢰 수
2. 챕터 0 튜토리얼 방식(§5-2): 단계 안내 메시지(플레이 중 메시지가 D-045 "대화는 시작·종료만"과 다름 — 튜토리얼 예외로 둘지), 게임오버 없음
3. 바탕화면 챕터 폴더(§5-3)
4. 조합 키 안(§4)과 `Shift + 영문` 1차 제외
5. 새 요소(§3-2): 감시 카메라 / 번호 장치 / 대상 2명 / 버티기
6. 의뢰 제작 규칙(§6)
