## 1. 왜 이 콘텐츠인가

- **제작 의도**: GitHub Game Off 2026(주제 SHIFT)에 1인으로 13일 안에 완성하는 포트폴리오 작품(D-001). 평가자는 짧게 플레이하고 6개 항목으로 평가한다.
- **핵심 재미**: SF 디스토피아의 뒷세계 해커가 되어 의뢰를 맡고, 간단한 조작키 조합으로 상황을 퍼즐처럼 푼다(D-013).
- 그래서 콘텐츠는
  1. **한 의뢰가 짧다** — 평가자가 몇 분 안에 핵심 재미를 느껴야 한다.
  2. **의뢰마다 새 것을 하나만 가르친다** — "Shift 하나에서 조합이 늘어나는" 진행(D-005)을 콘텐츠 순서로 보여 준다.
  3. **클리어는 쉽고, ★3은 어렵다** — 처음 보는 사람도 끝까지 가고, 잘하는 사람은 다시 도전한다(D-026~D-030).

## 2. 콘텐츠 구성 요소

| 요소 | 역할 | 상태 |
| --- | --- | --- |
| 의뢰(스테이지) | 퍼즐 한 판. 장면 격자 + 대상 + 칸·장치 + 미션 + 대화 | 구조 `[구현]`, 실제 의뢰는 테스트 1개 |
| 칸·장치 | 퍼즐의 규칙 조각(02-02 §4) | 7종 `[구현]`, 새 요소 `[제안]` |
| 미션 | 클리어 조건과 별 조건 | 최종 + 체크 지점 `[구현]` |
| 조합 키 | 의뢰가 진행될수록 늘어나는 조작 | `[제안]` — D-032 |
| 대화 | 의뢰의 이유와 해커의 성격을 전달(무뚝뚝 — D-052) | 구조 `[구현]`, 대사 임시 |
| 별·최고 기록 | 다시 도전할 이유 | `[구현]` |

## 3. 칸·장치 콘텐츠

### 3-1. 구현된 칸(7종)

바닥, 벽, 문, 방향 칸, 출구, 체크 지점, 중계기 — 규칙은 02-02 §4.

| 칸 | 퍼즐에서의 역할 |
| --- | --- |
| 문 | "언제 열어 둘까" — 대상이 지나가는 순간에만 짧게 연다(타이밍) |
| 방향 칸 | "어디로 보낼까" — 들어서는 순간에 방향을 바꿔 길을 고른다(경로 선택) |
| 체크 지점 | "더 갈까 멈출까" — 별을 위한 우회 경로를 만든다(위험과 보상) |
| 중계기 | "숨 돌리기" — 추적도를 회복시켜 다음 Shift를 쓸 여유를 준다(자원 관리) |

### 3-2. 새 요소 후보 `[제안]`

| 요소 | 규칙(안) | 퍼즐 역할 | 1차 범위 판단 |
| --- | --- | --- | --- |
| 감시 카메라 | 정해진 칸들을 비춘다. 시야 안의 칸에서 Shift를 누르면 추적도가 2배로 오른다 | "어디서 누를까" — 같은 문이라도 위치에 따라 비용이 다름 | 넣는 안. 기존 규칙(추적도)만 바꿔서 구현이 가볍다 |
| 번호 장치 | 문·카메라에 1~9 번호표. `Shift + 숫자`로 조준 없이 그 장치를 어긋나게 한다 | "멀리 있는 것을 동시에" — 조준 점프의 한계를 넘는다 | `Shift + 숫자`를 넣으면 같이 들어감 |
| 대상 2명 | 대상이 두 명. 각자 지정된 출구로 | "두 흐름을 동시에" — 최종 의뢰의 종합 시험 | 선택. 이동·미션 데이터를 늘려야 해서 중간 비용 |
| 버티기 의뢰 | 출구 대신 제한 시간 동안 게임오버 없이 버티면 클리어(특수 스테이지, D-027) | 추적도 관리만 집중 시험 | 선택. 일정 여유가 있으면 마지막에 |

## 4. 조합 키 콘텐츠 `[제안]` — D-032

키보드에서 원래 쓰는 뜻을 살린다(유사 게임 조사에서 "실제 기능과 다르다"는 비판이 있었음).

| 조합 | 원래 뜻 | 게임 안 의미 | 비용 |
| --- | --- | --- | --- |
| `Shift + 방향키` | 선택 영역 넓히기 | Shift를 누른 채 방향키를 누를 때마다 어긋남 범위가 그 방향으로 1칸 넓어짐. Shift를 떼면 범위 초기화 | 범위 칸 수에 비례해 추적도가 빨리 오름 |
| `Shift + 숫자` | 두 번째 기능 | 번호 장치를 원격으로 어긋나게 함(누르는 동안) | 기본과 같음 |
| `Shift + 영문` | 대문자 | **1차에서는 쓰지 않음**. 조합이 많아지면 "간단한 조합"(D-013)이 깨지고, 13일 일정에 비해 학습 부담이 큼 | — |

- 확장 방향: 2차 버전에서 `Shift + 영문`을 "같은 글자가 붙은 칸 묶음을 한꺼번에"로 넣을 수 있다.

## 5. 의뢰 라인업(1차) `[제안]`

### 5-1. 1차 범위와 이유

- **의뢰 5개**. 이유: 제출까지 남은 기간(11-18 ~ 12-01)에 기능 구현 3일 + 의뢰 제작·조정 4일을 잡으면 하루 1~2개를 다듬을 수 있다. 평가자 한 명이 전부 해 보는 데 10~15분 정도를 목표로 한다.
- **의뢰 하나의 크기(의도)**: 격자 12×5 ~ 13×7 칸, 미션 3개(최종 1 + 나머지 2), 첫 클리어 1~2분, ★1 경로에서 Shift 총 2~4초 사용.

### 5-2. 순서와 가르치는 것

| 의뢰 | 새로 배우는 것 | 의도 |
| --- | --- | --- |
| #01 | Shift 단독으로 문 열기, 방향 칸 꺾기 | 핵심 조작 하나만. 현재 테스트 의뢰를 다듬어 사용 |
| #02 | 중계기로 추적도 회복, 별을 위한 우회 | "자원을 쓰고 되찾는" 흐름 |
| #03 | `Shift + 방향키` 범위 넓히기 | 긴 벽 줄을 한 번에 어긋나게 해 지름길 — 대신 추적도가 빨리 오름 |
| #04 | 감시 카메라 + `Shift + 숫자` 번호 장치 | 비싼 칸을 피하거나, 카메라를 원격으로 돌림 |
| #05 | 종합(범위 + 번호 + 카메라, 선택: 대상 2명) | 배운 것을 모두 씀 |

### 5-3. 난이도 흐름(의도)

| 의뢰 | ★1 난이도 | ★3 난이도 |
| --- | --- | --- |
| #01 | 매우 쉬움(튜토리얼) | 쉬움 |
| #02 | 쉬움 | 보통 |
| #03 | 보통 | 보통 |
| #04 | 보통 | 어려움 |
| #05 | 보통~어려움 | 어려움 |

## 6. 의뢰 제작 규칙 `[제안]`

1. 모든 의뢰는 **★1 경로가 반드시 있다**. ★1은 그 의뢰의 새 요소만 이해하면 갈 수 있게 한다.
2. **★3 경로는 위험을 진다**: 추적도를 더 쓰거나, 카운트다운에 들어갈 수 있는 길로 둔다.
3. 중계기는 ★3 경로 위나 그 근처에 둔다(위험을 진 사람에게 회복 수단).
4. 새 요소는 처음 나올 때 **안전한 곳에서 한 번** 써 보게 한다(실패 비용이 낮은 위치).
5. 대화(브리핑)는 3~5줄. 이번 의뢰의 목표와 새 요소를 한 줄로 알려 준다. 해커는 짧게 답한다(D-052).
6. 의뢰 데이터는 두 층 문자 격자 + 미션 목록 + 대화로 만든다(현재 구현 형식).

## 7. 확장 방향(2차 이후)

- `Shift + 영문` 묶음 조작, 대상 여러 명, 버티기 외 특수 스테이지(시간 제한 탈출 등)
- 의뢰인 초상(MVP는 주인공만 — D-047)
- 주인공 이야기를 잇는 의뢰 묶음(시나리오 기획)

## 8. 정할 것

1. 조합 키 안(§4) 채택·수정
2. `Shift + 영문` 1차 제외 여부
3. 새 요소(§3-2) 중 넣을 것: 감시 카메라 / 번호 장치 / 대상 2명 / 버티기
4. 의뢰 수(5개)와 순서(§5-2)
5. 의뢰 제작 규칙(§6) 채택
