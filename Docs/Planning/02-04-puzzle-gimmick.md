## 1. 퍼즐 구조

### 1-1. 퍼즐을 이루는 요소

| 요소 | 역할 | 예 |
| --- | --- | --- |
| 대상(의뢰 대상) | **정해진 규칙대로 움직이는 퍼즐 조각**. 플레이어가 직접 조종하지 않는다 | 걷기, 문 앞 기다림, 끝 벽 돌아섬 |
| 길(섹터 연결) | 대상이 갈 수 있는 경로의 그래프 | 같은 층 좌우, 계단·엘리베이터로 층 이동 |
| 관문 | 길을 막거나 여는 것 → **타이밍** | 문, 차단막 |
| 분기 | 대상이 어느 길로 갈지 바꾸는 것 → **경로 선택** | 계단, 엘리베이터 |
| 목표 | 미션 | 출구(최종), 단말(나머지) |
| 자원 | 추적도와 회복 | 추적도, 중계기 |
| 위험 | 자원 소비를 키우는 것 → **장소 선택** | 감시 카메라(챕터 2) |

### 1-2. 플레이어 동사

| 동사 | 키 | 챕터 |
| --- | --- | --- |
| 고르기(조준) | 방향키 단독 | 0~ |
| 바꾸기(상태 어긋남) | 왼쪽 Shift | 0~ |
| 옮기기(위치 어긋남) | `Shift + 방향키` — §2 | 1~ |
| 멀리서 동시에(원격 어긋남) | `Shift + 숫자` — §2 | 2~ |

→ 챕터가 올라갈수록 "무엇을, 어디서, 몇 개를 동시에" 조작하는지가 넓어진다.

### 1-3. 퍼즐 유형 4가지

| 유형 | 질문 | 주로 쓰는 요소 |
| --- | --- | --- |
| 타이밍 | "언제 열까?" | 관문 |
| 경로 | "어느 길로 보낼까?" | 분기 |
| 자원 | "어디에 추적도를 쓸까?" | 추적도·중계기·카메라 |
| 동시 처리 | "두 가지를 한 번에 할 수 있나?" | 원격 조작(챕터 2), 범위 |

### 1-4. 의뢰 하나의 3단 구조

1. **도입**: 새 요소를 실패해도 괜찮은 곳에서 한 번 써 보게 한다.
2. **적용**: 출구로 가는 필수 길에서 새 요소를 반드시 쓰게 한다(★1).
3. **응용**: 나머지 미션(★2·★3)은 새 요소를 앞 챕터 요소와 섞어 쓰게 하고, 추적도 위험을 진다.

### 1-5. 난이도 손잡이

| 손잡이 | 쉽게 | 어렵게 |
| --- | --- | --- |
| 관문 사이 거리 | 멀다(조준을 옮길 시간 여유) | 가깝다(연속 조작) |
| 화면 밖 요소 | 없음 | 조작할 섹터가 대상과 다른 화면 |
| 동시 관문 수 | 1 | 2 이상 |
| 추적도 예산 | 넉넉함, 중계기가 길 위 | 빠듯함, 중계기가 우회로 |
| 대상 속도 | 느림 | 빠름 |

### 1-6. 막힘(소프트락) 방지 규칙

- 대상은 끝 벽에서 돌아서므로 같은 층에서 영원히 갇히지 않는다(02-02 §0-2).
- 모든 의뢰는 처음부터 다시 시작(일시정지 메뉴)으로 빠져나올 수 있다.
- 한 번 지나가면 돌아올 수 없는 길(일방통행 계단 등)은 그 뒤에 ★1 경로가 남아 있을 때만 둔다.

### 1-7. 밸런스와의 연결

- 퍼즐의 "타이밍" 유형이 살려면 **관문을 짧게 한 번만 눌러서 통과하는 문제**(03-02 §3-1)를 막아야 한다.
- 추천: 03-02 **안 A**(대상이 관문을 완전히 지나갈 때까지 열려 있어야 함). 그래야 "얼마나 오래 열어 둘지"가 퍼즐이 된다.

## 2. 조작키별 기믹

### 2-1. 챕터 0 — 왼쪽 Shift: 상태 어긋남(구현됨)

조준한 섹터·오브젝트가 설계도 상태로 바뀐다. 문(닫힘↔열림), 계단 셔터, 엘리베이터(멈춤↔작동), 차단막(섹터 전체).

### 2-2. 챕터 1 — `Shift + 방향키`: 위치 어긋남 `[제안·추천]`

**키보드에서 원래 쓰는 뜻**: 선택한 것을 그 방향으로 옮기기·넓히기. **"세밀한 조정"을 이 키에 담는다.**

- 규칙: Shift를 누른 채 방향키를 누르면 조준한 섹터의 **이동형 오브젝트가 설계도 상의 위치로 그 방향을 향해 한 단계씩 어긋난다**. 최대 단계는 오브젝트마다 정함(예: 1~3단계, 한 단계 = 16px 또는 한 층 높이). Shift를 떼면 원래 위치로 돌아간다(D-010).
- 비용: 단계가 클수록 추적도가 빨리 오른다(예: 초당 증가 × 단계 수) — 03-02와 함께 조정.
- "만들기"가 아니라 **이미 있는 물체를 옮기는 것**이라 D-015를 지킨다.

| 새 환경 요소(물류 지구) | 위치 어긋남 | 퍼즐 |
| --- | --- | --- |
| 이동식 발판 | 끊어진 바닥 사이로 좌우로 밀어 다리를 만듦 | 대상이 건너는 동안 계속 붙잡고 있어야 함(타이밍 + 자원) |
| 화물 리프트 | 위아래로 한 층 올리고 내림 | 계단 없이 층 이동. 대상이 올라탄 순간 올려야 함 |
| 컨테이너 | 통로를 막은 화물을 옆으로 밀어 길을 엶 | 밀어 둔 동안만 길이 열림. 넓게 밀수록 비쌈 |
| 컨베이어 | 벨트 방향을 바꿔 대상이 실려 가는 방향을 바꿈 | 분기 — 어느 쪽으로 보낼지 |

대안 `[제안]`: **범위 넓히기** — Shift를 누른 채 방향키를 누를 때마다 어긋남 범위가 이웃 섹터로 넓어짐(문서·파일 선택 확장과 같은 뜻). 여러 관문을 한 번에 열지만 범위만큼 비쌈. 기존 오브젝트만으로 구현할 수 있어 가볍지만, "세밀한 조정"과는 거리가 있다.

### 2-3. 챕터 2 — `Shift + 숫자`: 원격 어긋남 `[제안·추천]`

**키보드에서 원래 쓰는 뜻**: 숫자 키의 두 번째 기능. 번호가 붙은 것을 바로 부름.

- 규칙: 화면 속 일부 장치에 **번호표(1~9)**가 붙어 있다. `Shift + 숫자`를 누르는 동안 그 번호의 장치가 조준과 상관없이 설계도 상태가 된다. 조준한 섹터의 Shift 효과와 **동시에** 쓸 수 있다(왼쪽 Shift는 이미 눌려 있으므로).
- 비용: 원격 장치 하나당 추적도가 추가로 오른다(조준 + 원격 = 2배).

| 새 환경 요소(감시 구역) | 원격 어긋남 | 퍼즐 |
| --- | --- | --- |
| 번호 문·셔터 | 멀리 있는 문을 조준 없이 엶 | 화면 밖 관문을 처리하며 화면 안 관문도 동시에 |
| 감시 카메라(번호) | 시야를 다른 쪽으로 돌림 | 카메라 시야 안의 섹터에서 Shift를 쓰면 추적도 2배 → 먼저 카메라를 돌려 두고 조작 |
| 경보 패널 | 경보를 잠깐 꺼서 중계기처럼 쓰는 대신 위험 | 자원 판단 |

대안 `[제안]`: **어긋남 단계 고르기** — 숫자가 단계(엘리베이터 층 1~9, 셔터 높이 등)를 고른다. 세밀하지만, 챕터 1의 위치 어긋남과 역할이 겹친다.

### 2-4. 챕터 3(선택) — `Shift + 영문`

1차 범위에서는 제외(02-03 §4). 일정이 남으면 "같은 글자 꼬리표가 붙은 섹터 묶음을 한 번에"로 검토.

## 3. 챕터별 퍼즐 흐름 예 `[제안]`

| 챕터 | 의뢰 1(도입·적용) | 의뢰 2(응용) |
| --- | --- | --- |
| 0 | 문 타이밍(구현됨) | 계단 분기 + 차단막 + 중계기, 되돌아가기 ★3(구현됨) |
| 1 물류 지구 | 이동식 발판으로 끊긴 바닥 건너기 → 컨테이너 밀어 길 열기 | 화물 리프트로 층 이동 + 컨베이어 분기 + 문 타이밍(챕터 0 요소와 섞기) |
| 2 감시 구역 | 번호 문을 원격으로 열며 앞 문은 조준으로 동시 처리 | 카메라 시야를 돌려 두고 이동식 발판 조작, 경보 패널 자원 판단 |

## 4. 구현 비용 추정 `[제안]`

| 기믹 | 새로 필요한 것 | 크기 |
| --- | --- | --- |
| 챕터 1 위치 어긋남 | 이동형 오브젝트(위치 단계), 대상이 발판·리프트 위에 있는 판정, 그림 4종 | 중간~큼 |
| 챕터 1 대안(범위) | 조준 범위 확장, 범위 표시 | 작음 |
| 챕터 2 원격 어긋남 | 번호표, 동시 어긋남 판정, 카메라 시야·비용 배수, 그림 3종 | 중간 |
| 밸런스 안 A | 관문 통과 판정 변경 | 작음 |

남은 일정(제출 12-01)을 생각하면 **챕터 1은 이동식 발판·컨테이너 2종부터**, 리프트·컨베이어는 여유가 있을 때 추가하는 순서를 추천한다.
