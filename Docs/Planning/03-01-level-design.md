> 표기: `D-ID`는 사용자 결정, `[제안]`은 에이전트 제안(미확정)이다. **이 문서의 내용은 아직 모두 제안이다.**

## 1. 이 문서가 정할 것

- 조합 키(`Shift + 방향키·숫자·영문`)의 의미와 등장 순서 — D-032
- 미션·트리거 종류, 특수 스테이지 — D-021, D-027
- MVP-2 의뢰 수와 난이도 흐름
- 제약: 왜곡 = 어긋남(D-015), 층 2개(D-018), 실시간(D-009), 누르는 동안만(D-010), 한 번에 최대 키 2개(리스크 표), 간단한 조합(D-013)

## 2. 조합 키 후보 `[제안]`

키보드에서 원래 쓰이는 뜻을 살린다(실제 의미와 다르다는 비판을 피하기 위해 — 유사 게임 조사).

| 조합 | 원래 뜻 | 게임 안 의미 | 추적도 |
| --- | --- | --- | --- |
| `Shift + 방향키` | 선택 영역 넓히기(문서·파일 선택) | Shift를 누른 채 방향키를 누르면 **어긋남 범위가 그 방향으로 1칸씩 넓어진다**. 떼면 범위 초기화 | 범위 칸 수만큼 빨리 오름 |
| `Shift + 숫자` | 기호 입력(두 번째 기능) | 화면 속 **번호가 붙은 장치(1~9)를 조준 없이 원격으로 어긋나게** 한다(번호 = 감시 카메라·문 패널 ID) | 기본과 같음 |
| `Shift + 영문` | 대문자(두 번째 상태) | MVP-2에서는 쓰지 않는 안을 제안. 조합이 늘어나면 "간단한 조합"(D-013)을 해치고 13일 일정에 무리 | — |

- 탭 전환 `]`(D-050)는 시스템 키라 위와 겹치지 않는다.

## 3. 칸·미션·트리거 후보 `[제안]`

| 종류 | 내용 | 등장 |
| --- | --- | --- |
| 문·방향 칸 | 이미 구현(MVP-1) | 1~ |
| 체크 지점 | 이미 구현. 나머지 미션 | 1~ |
| 중계기 | 이미 구현. 추적도 감소 트리거 | 2~ |
| 감시 카메라 | 시야 칸에서 Shift를 누르면 추적도가 2배로 오름. 카메라도 번호 장치라 `Shift + 숫자`로 잠깐 다른 곳을 보게 할 수 있음 | 4~ |
| 대상 2명 | 서로 다른 출구로 보내야 하는 의뢰 대상 2명 | 5 |
| 특수 스테이지 | 출구 대신 **제한 시간 동안 버티기**(최종 미션 = 시간 생존) | 마지막(선택) |

## 4. MVP-2 의뢰 흐름 `[제안]` — 5개

| 의뢰 | 새로 배우는 것 | 미션 예시 |
| --- | --- | --- |
| #01 | Shift 단독, 문 열기 | 출구 도달 + 체크 지점 2 (현재 테스트 의뢰를 다듬어 사용) |
| #02 | 방향 칸 꺾기 + 중계기로 추적도 회복 | 출구 + 체크 지점 + 중계기 |
| #03 | `Shift + 방향키` 범위 넓히기 | 긴 벽 줄을 한 번에 어긋나게 해 지름길 |
| #04 | `Shift + 숫자` 번호 장치 + 감시 카메라 | 카메라 시야를 돌리고 통과 |
| #05 | 종합(범위 + 번호 + 대상 2명) | 두 대상을 각자 출구로 |

- 일정: 레벨 기획 확정 11-18 → 기능 구현(조합 키·카메라·대상 2명) 11-19~21 → 의뢰 5개 제작·조정 11-22~25 → QA → 빌드(사용자 요청 시, QA 이후)

## 5. 정할 것

1. 조합 키 안(위 표) 채택·수정 여부
2. `Shift + 영문`을 MVP-2에서 뺄지
3. 새 요소(감시 카메라, 대상 2명, 버티기 특수 스테이지) 중 넣을 것
4. 의뢰 수(5개 제안)와 순서
