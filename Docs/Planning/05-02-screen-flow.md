- **연관 문서**: [05-01-ui-layout.md](./05-01-ui-layout.md), [02-01-system-design.md](./02-01-system-design.md), [decisions.md](./decisions.md)
- **담당 AI**: Claude Code(Opus, 설계)

> 표기: `D-ID`는 사용자 결정, `[제안]`은 에이전트 제안(미확정)이다.

## 1. 범위

- 게임을 실행하면 **메인 화면**과 **스테이지(의뢰) 선택 화면**을 거쳐 스테이지로 들어간다. 이 흐름을 만들고 연결한다 — D-055
- MVP-1 범위(D-034)에서 제외했던 "의뢰 선택 화면"을 이번에 추가한다(D-055가 범위를 넓힘)

## 2. 화면 흐름

```
[부팅] → [메인] ─START─→ [의뢰 선택] ─ENTER─→ [의뢰: 브리핑 대화 → 플레이 → 결과]
            │                 ↑   │ESC                         │
            │CREDITS          │   └──────→ [메인]               │
            ↓                 └──────────── 결과에서 ENTER ─────┘
         [크레딧] ─ESC─→ [메인]
의뢰 중 ESC → 일시정지 [계속 / 다시 시작 / 의뢰 선택으로]
```

| 화면 | 들어오는 길 | 나가는 길 |
| --- | --- | --- |
| 메인 | 부팅, 의뢰 선택에서 ESC, 크레딧에서 ESC | START → 의뢰 선택, CREDITS → 크레딧 |
| 의뢰 선택 | 메인 START, 결과 화면 ENTER, 일시정지 "의뢰 선택으로" | ENTER → 선택한 의뢰, ESC → 메인 |
| 의뢰 | 의뢰 선택 ENTER | 결과 후 의뢰 선택, 일시정지 메뉴 |
| 크레딧 | 메인 CREDITS | ESC → 메인 |

- 조작: 방향키로 고르고 Enter로 결정, ESC는 뒤로·일시정지 — D-036, D-037. 화면마다 시스템 키를 표시한다 — D-051
- 브리핑·결과 대화(D-045)는 의뢰 화면 안의 단계다. 대화 시스템 구현은 별도 작업(W-003)에서 하고, 이번에는 자리만 둔다 `[제안]`

## 3. 메인 화면 `[제안]`

- 도시 야경 배경 레이어(D-041) + 가제 로고 + 메뉴(START, CREDITS) + "PRESS ENTER" 안내
- 로고: 도트 글자를 3배로 키우고, 설계도 층 색으로 몇 픽셀 **어긋난 사본**을 뒤에 깔아 SHIFT를 표현(D-015)
- 로고 글자는 **임시 표기**다. 게임 제목은 사용자가 나중에 정한다
- Web 빌드라 QUIT 항목은 두지 않는다
- 크레딧 화면: 제작자, 사용 도구, AI 사용 공개(행사 규칙), 제3자 에셋

## 4. 의뢰 선택 화면 `[제안]`

- 해커의 **의뢰 게시판(REQUEST BOARD)** 형식. 프로그램 창 안에 왼쪽 의뢰 목록, 오른쪽 상세
- 의뢰 카드: 번호, 의뢰인, 제목, 상태(NEW / CLEAR / LOCKED), 획득 별
- 상세: 의뢰 요약 1~2줄, 미션 목록, 최고 별 기록
- 잠금: 앞 의뢰를 클리어하면 다음 의뢰가 열린다(★1 이상)
- 지금 의뢰는 테스트 의뢰 1개뿐이다. 나머지 칸은 잠긴 빈 자리(`???`)로 보여 준다. 실제 의뢰 목록은 레벨 기획에서 정한다(D-032)

## 5. 진행 저장 `[제안]`

- 의뢰별 최고 별과 잠금 해제 상태만 저장한다(Unity PlayerPrefs — Web에서는 브라우저 저장소)
- 저장이 실패해도 게임은 진행된다(그 세션 동안만 유지)
- 개인 정보는 저장하지 않는다
