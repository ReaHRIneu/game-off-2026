## 1. 서사의 무게 — D-072

- 이 게임은 **퍼즐 중심**이고 서사는 **가볍게** 둔다.
- 서사는 의뢰 시작·종료 때 문자 메시지 2~4줄(D-045, D-046)로만 전한다. 설명 장면·컷신은 만들지 않는다 `[제안]`
- 대사는 짧게. 주인공은 말수가 적고 무뚝뚝하다(D-052).

## 2. 조력자의 개연성 — D-071 (A 계약형 + C 도주형)

| 질문 | 답 |
| --- | --- |
| 왜 해커의 건물에 들어왔나 | 도시 단속을 피해 도망치던 중(C), 숨을 곳과 팔 물건이 필요해 낡은 건물에 숨어듦(A) |
| 해커는 왜 신고하지 않나 | 신고하면 단속반이 건물을 뒤지고, 해커 자신의 불법 장비도 드러난다. 마침 **현장에서 움직일 사람**이 필요했다 |
| 조력자는 왜 돕나 | 로비 단말에 **얼굴이 기록**되어 약점이 잡혔고(A), 해커가 도시 기록에서 **수배 정보를 지워 주는** 대가를 제시한다. 갈 곳도 없다(C) |
| 관계 | 처음에는 약점과 거래로 묶인 계약. 의뢰를 거치며 조금씩 신뢰 `[제안]` |

- 게임 규칙 설명과 맞물림: 조력자는 **앞만 보고 가는 사람**이고, 막히면 **해커의 신호를 기다린다** → 대상 이동 규칙(직진, 문 앞 기다림, 끝 벽 돌아섬)의 이유.

## 3. 인물 `[제안]`

| 인물 | 역할 | 메모 |
| --- | --- | --- |
| 주인공(해커) | 플레이어. 원격 조작 | 이름 미정. 대화 표시 `ME` |
| 조력자 | 화면 속에서 움직이는 인물(D-070) | 이름 미정. 대화 표시는 이름(초상 없음 — 범위는 확인 대기, D-047). 성격: 말이 많고 겁이 없음(무뚝뚝한 주인공과 대비) |
| 의뢰인 | 챕터 1~ 의뢰를 맡기는 쪽 | 이름표만. 그림 없음 |

## 4. 챕터 흐름(한 줄씩) `[제안]`

| 챕터 | 서사 한 줄 | 퍼즐과의 관계 |
| --- | --- | --- |
| 0 | 밤, 주인공의 건물에 누군가 숨어든다. 가둬 놓고 보니 쫓기는 좀도둑 → 거래 | 침입자 저지 튜토리얼(D-069) |
| 1 | 수배를 지우려면 돈과 정보가 필요하다. 구시가지 빌딩을 넘나드는 첫 의뢰들 | 조력자 안내 시작(D-067) |
| 2 | 사람이 없는 공장지대의 의뢰. 조력자를 쫓던 단속과 관련된 단서가 나온다(가벼운 떡밥) | D-068 |

## 5. 챕터 0 대사 초안 `[제안]` — 영문(UI 영문), 화자 `???`는 조력자(이름 공개 전)

- 얼굴 기록은 미션이 아니라 대사로만 전한다(튜토리얼은 성급·나머지 미션 없음, D-074). 건물 보안 카메라가 이미 찍어 두었다는 설정 `[제안]`
- 화자 `SYSTEM`은 건물 보안 시스템 알림(왼쪽 말풍선, 이름만)
